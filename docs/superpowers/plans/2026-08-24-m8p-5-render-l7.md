# M8P-5 Deterministic Tailored Render and L7 Execution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Render an accepted tailored draft through the already-selected LaTeX arm, prove the PDF still says what the draft meant — including real rendered line counts — and publish the result atomically under a deterministic per-application layout.

**Architecture:** A pure mapper re-hydrates identity/education/ATS policy from the local master profile and binds the draft to it by alignment fingerprint. A new geometry module reads line- and character-level PDF structure so L7 can measure what container-level parsing cannot. Publication is fail-closed and idempotent, with `render_result.json` written last as the commit marker.

**Tech Stack:** Python 3.11+, frozen dataclasses, existing `pdfminer.six`, existing `pdflatex` arm, stdlib `hashlib`/`json`/`pathlib`/`tempfile`, pytest.

**Spec:** `docs/superpowers/specs/2026-08-24-m8p-5-render-l7-design.md`

**Can implementation start before M8P-3R merges?** M8P-3R **merged at `560ad8d`**, so the whole milestone is unblocked. Tasks 1–4 were designed to be parallel-safe regardless (they consume only `TailoredDraft` dataclass fields and PDF geometry); Task 5 is now a cheap confirmation rather than a wait, and Task 6 may follow immediately.

class RenderOutcomeKind(str, Enum):
