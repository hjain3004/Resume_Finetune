# M8P-1 — Human-Pilot S1 Contract & Trace Foundation (design record)

Status: approved and implemented, 2026-08-21.
Phase: 3 (M8 Tailoring), first increment of live tailoring.

This is a bounded design record documenting the decisions fixed by the
approved M8P-1 implementation prompt. It introduces no new architecture
beyond what that prompt specified; it exists so a future session can see
what was decided and why without re-deriving it from the implementation
prompt or the code.

## 1. Purpose and scope

M8P-1 builds and offline-verifies the **S1 requirement-extraction contract
and trace foundation** for the eventual three-resume human-evaluated
tailoring pilot (jobs 119 — Cisco, 225 — Notion, 211 — Citadel). It replaces
the unsafe legacy `src/tailor/wrapper.py` single-shot invocation path with a
typed, strictly validated, traced S1 stage.

**In scope:** S1 typed contracts, strict parser + JD-anchored semantic
validation, protected S1 prompt template, safe tool-disabled invocation
wrapper, I11 tracing, read-only job-preparation DB boundary, a narrow
`prepare`/`invoke` CLI, and disabling the legacy invocation path.

**Explicitly out of scope (see §9):** S0, S2, S3, G1 completion, G2, G3, PDF
rendering, Company Bank integration, DB status mutation, batch mode, and any
live model invocation. No resume has been generated by this increment.

## 2. O1 resolution — wrapper-invoked, pure text-in/text-out

`docs/superpowers/specs/2026-08-04-m8-live-tailoring-decisions.md` left O1
(manual vs. wrapper-invoked model call) unresolved. **M8P-1 resolves O1 as
option (a): the wrapper builds one self-contained prompt, invokes `claude -p`
with tools disabled and session persistence disabled, reads stdout only, and
owns every filesystem write.** The model:

- receives no filesystem path and no tools;
- cannot read or write repository files;
- receives no master profile, contact details, Company Bank data, scoring
  rationale, or previous application data;
- returns JSON text only, to stdout.

This mirrors the existing scoring trust boundary
(`scripts/score_batch.py`'s `DEFAULT_CLAUDE_CMD`), extended into a
dedicated, narrowly scoped module (`src/tailor/invoke.py`) rather than
duplicating the command shape inline.

## 3. Module layout

```
src/tailor/s1.py           typed dataclasses, strict parser, JD-anchored
                            semantic validation, request (de)serialization,
                            prompt building. Pure -- no filesystem I/O.
src/tailor/invoke.py       safe, tool-disabled subprocess invocation.
                            Injectable command, explicit timeout, no shell,
                            no retries.
src/tailor/s1_pipeline.py  orchestration: build prompt -> invoke -> I11
                            trace -> parse -> classify into one
                            S1OutcomeKind. Owns filesystem I/O the pure
                            parser does not.
scripts/tailor_s1.py       CLI: `prepare` (read-only DB -> deterministic
                            s1_request.json) and `invoke` (validated
                            request -> model call -> trace -> atomic
                            s1.json), with `invoke --dry-run`.
docs/prompts/tailoring_s1.md   the S1-only prompt template.
```

## 4. S1 contract

Frozen dataclasses exactly as specified in the approved implementation
prompt: `Requirement{term, quote}`, `AnchoredSummary{summary, quote}`,
`AnchoredClaim{claim, quote}`, `CompanyContext{domain, product,
stage_or_scale}` (each field independently nullable), `InjectionFlag{quote,
reason}`, `S1Request{job_id, company, title, jd_text, jd_quality}`,
`S1Response{must_have, nice_to_have, responsibilities_summary,
seniority_signals, disqualifiers, company_context, suspected_injection}`.

`parse_s1_response(raw_output: str, jd_text: str) -> S1Response` is pure and
performs two distinct classes of validation, kept as separate exception
types (`S1ParseError` vs. `S1SemanticError`) so the orchestrator can report
them as distinct outcomes:

- **Structural (`S1ParseError`):** strict `json.loads` only (no markdown-
  fence stripping, no trailing-comma repair); every object at every level
  rejects unexpected fields and requires all its fields; every string field
  is rejected if empty; normalized-duplicate requirement terms are rejected
  within or across `must_have`/`nice_to_have`; exact-duplicate quotes are
  rejected within `seniority_signals`/`disqualifiers`. All-null
  `company_context` (all three subfields `null`) normalizes to `None`.
- **Semantic (`S1SemanticError`):** every `quote` must be an exact,
  case-sensitive substring of the stored `jd_text`; every `term` must be an
  exact, case-sensitive substring of its own `quote`. This is the
  anti-hallucination device from `TAILORING_METHODOLOGY.md` §3 ("a term
  without a quote is invalid") made mechanically enforceable.

All diagnostics that echo untrusted content (raw model output, JD
substrings) are bounded to 200 characters.

## 5. Injection handling (I12)

`suspected_injection` is not itself an error — S1 does not obey instructions
found inside `jd_text`; it reports them as data, per I12
(`docs/SELF_HEALING.md`). A nonempty `suspected_injection` list is valid
evidence of a structurally and semantically sound response, but the
orchestration layer classifies it as `S1OutcomeKind.INJECTION_BLOCKED`
rather than `VALID`: the CLI does not publish `s1.json` for an
injection-flagged response. Downstream tailoring on that job is blocked
pending human review. **No database mutation happens in this increment** —
there is no `flags` write, no status transition; blocking is purely "the
CLI declines to publish an artifact for this attempt."

## 6. Tracing (I11)

`run_s1_invocation()` calls the existing `src.llm_trace.write_trace()` for
every completed attempt where raw stdout exists — including malformed
output (`PARSE_FAILURE`), JD-anchoring failures (`SEMANTIC_FAILURE`),
injection-blocked responses, and a nonzero exit that still produced partial
stdout. It does **not** trace a timeout or an empty-stdout failure, because
there is no raw output to archive. No parallel trace mechanism was built;
`write_trace()` needed no extension because the S1 CLI always has a real
`s1_request.json` on disk (written by `prepare`) to pass as the traced input
path, and the S1 prompt template file itself is hashed exactly as
`scripts/score_batch.py` hashes `docs/scoring_prompt.md`.

## 7. Job preparation

`src.db.prepare_tailoring_request(conn, job_id) -> S1Request` is read-only
and requires, in order: `job_id` not in `{229, 279}` (the two jobs the Phase
2 closure excluded from live tailoring — see `docs/ROADMAP.md` 2026-07-25);
row exists; `status == SHORTLISTED`; `jd_quality == "ats"`; nonempty
`jd_text`; `base_variant in {"backend", "ml"}`. It never mutates the row.
The CLI's `prepare` subcommand opens the DB via
`db.get_readonly_connection()` (existing `mode=ro` URI helper), so a bug in
this path cannot write to the production DB even accidentally.

## 8. Artifact publication boundary

`S1OutcomeKind` distinguishes `INVOCATION_FAILURE`, `PARSE_FAILURE`,
`SEMANTIC_FAILURE`, `INJECTION_BLOCKED`, and `VALID`. The CLI's `invoke`
subcommand publishes `s1.json` (via a temp-file-plus-`os.replace` atomic
write, matching the existing pattern in `src/calibration.py` and
`scripts/company_bank.py`) only for `VALID`. Every other outcome leaves any
previously published `s1.json` untouched and exits nonzero. Raw model
output lives only in the immutable trace, never as (or inside) the
authoritative artifact.

## 9. What remains unimplemented after M8P-1

Per the approved prompt's explicit non-goals: S0 positioning, S2 selection,
S3 rewriting, G1 completion (L1/L4 still absent), G2 critic, G3 review
packet, PDF rendering, Company Bank lookup/Track C, application archival,
golden-set promotion, taste capture, gap aggregation, batch tailoring, the
30-resume dry run, database status mutation, and M9F-1/M9D work. No live S1
invocation occurred during this increment — jobs 119, 225, and 211 were not
touched by any model call, and no pilot artifacts were written.

Next milestone: **M8P-2 — S0 positioning brief + S2 structural selection**,
for one-job-at-a-time, JD-only operation (Company Bank remains optional and
unavailable).
